# 비기능 요구사항

## 성능

- 공개 사이트는 정적 파일로 제공한다.
- 홈의 초기 JavaScript와 이미지 전송량은 [성능 예산](../08-quality/performance-budget.md)을 준수한다.
- 지도는 iframe으로 삽입하지 않고 외부 링크로 제공한다.
- 아래쪽 갤러리 이미지는 지연 로딩한다.
- 이미지의 고정 크기 또는 종횡비를 선언해 레이아웃 이동을 방지한다.

## 가용성

- 공개 사이트는 Directus 또는 PostgreSQL 장애 시에도 마지막 정상 릴리스로 계속 서비스되어야 한다.
- CMS 장애는 콘텐츠 편집만 제한해야 하며 고객 사이트 장애로 전파되면 안 된다.
- 콘텐츠 빌드 실패 시 공개 산출물을 교체하지 않는다.

## 접근성

- 공개 사이트는 WCAG 2.2 AA를 목표로 한다.
- 키보드, 터치, 스크린리더 이름, 포커스 표시, 모션 감소를 지원한다.
- 색상만으로 상태를 전달하지 않는다.
- 핵심 터치 대상은 44×44 CSS px 이상을 내부 기준으로 한다.

## 보안

- 관리자와 공개 사이트를 논리적으로 분리한다.
- Public role은 기본 무권한이다.
- 빌드 토큰은 읽기 전용이며 브라우저 번들에 포함하지 않는다.
- 관리자 계정은 2단계 인증을 사용한다.
- 비밀값은 환경변수와 제한된 운영 저장소에서 관리한다.

## 유지보수

- 제품·CMS·인프라 계약은 문서와 스키마 스냅샷으로 버전 관리한다.
- Docker 이미지는 검증된 명시 버전 또는 digest로 고정한다.
- 자동 업데이트로 운영 서비스를 즉시 변경하지 않는다.
- 백업과 복구 테스트를 정기 수행한다.

## SEO

- 핵심 정보와 공개 콘텐츠는 빌드 시 HTML에 포함한다.
- 모든 공개 URL은 canonical을 갖는다.
- title과 description은 페이지별로 고유하고 실제 콘텐츠와 일치해야 한다.
- robots와 sitemap을 제공하고 Google·Naver 관리도구에 제출한다.
- 검색 노출이나 순위는 출시 승인 조건으로 보장하지 않는다.
