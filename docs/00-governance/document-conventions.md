# 문서 작성 규칙

## 기본 원칙

1. 문서는 한국어로 작성한다.
2. 코드 식별자, 환경변수, URL path는 원문 표기를 유지한다.
3. 사실, 결정, 제안, 미확정을 구분한다.
4. 구현과 충돌하는 문서는 구현 PR에서 즉시 갱신한다.
5. 같은 사실을 여러 문서에 복제하지 않고 기준 문서로 링크한다.
6. 비밀값과 실제 관리자 계정 정보는 문서에 기록하지 않는다.

## 문서 헤더

모든 기준 문서는 YAML front matter를 사용한다.

```yaml
---
title: "문서 제목"
status: "approved | proposed | draft | deprecated"
owner: "문서 책임자"
reviewers: "검토자"
last_updated: "YYYY-MM-DD"
review_trigger: "재검토 조건"
---
```

## 규범 표현

| 표현 | 의미 |
|---|---|
| `반드시` | 위반 시 결함 또는 출시 차단 |
| `금지` | 사용하지 않음 |
| `권장` | 합리적 이유가 있으면 예외 가능 |
| `가능` | 선택 사항 |
| `TBD` | 결정되지 않음 |
| `확인 필요` | 외부 사실이나 운영자 확인이 필요 |
| `출시 차단` | 확인 전 운영 배포 금지 |

## 링크

- 저장소 내부 문서는 상대 경로로 연결한다.
- 공식 기술 근거는 [공식 참고자료](references.md)에 모은다.
- 외부 자료를 인용할 때 접근일을 함께 기록한다.
- 삭제된 문서는 대체 문서로 연결하는 짧은 안내를 남긴다.

## 문서 변경 검토

다음은 최소 검토 항목이다.

- 내용이 현재 ADR과 충돌하지 않는가
- 확정되지 않은 값을 확정처럼 표현하지 않았는가
- 코드와 필드명이 일치하는가
- 상대 링크가 유효한가
- 운영 명령이 파괴적이라면 백업·롤백 조건이 있는가
- 외부 정책이나 라이선스 정보가 최신 확인을 요구하는가
