# 완료 정의

Issue는 아래 조건을 모두 충족해야 `READY`다.

## 제품

- 수용 기준이 관찰 가능한 형태로 통과했다.
- 모바일 고객 흐름이 끊기지 않는다.
- 외부 CTA가 정확한 채널로 연결된다.
- 미확정 콘텐츠는 확정처럼 표시되지 않는다.

## 코드

- 타입 검사와 린트가 통과한다.
- `output: 'export'` 빌드가 성공하고 `out/`이 생성된다.
- 런타임 서버 기능을 우회적으로 도입하지 않았다.
- 환경별 비밀값이 코드에 포함되지 않았다.
- 공개 사이트가 관리 backend 장애 시에도 동작한다.

## 데이터·관리 backend

- schema 변경이 Flyway migration과 문서에 반영됐다.
- 관리자 API는 request field allowlist와 인증·인가 경계를 자동 test로 검증한다.
- `draft`와 `archived` 콘텐츠가 공개 산출물에 포함되지 않는다.
- 게시·수정·보관이 정적 배포까지 정상 연결된다.

## 품질

- 핵심 경로 자동 테스트가 통과한다.
- 실제 모바일 기기에서 CTA, 필터, 모달, 스크롤을 확인한다.
- 키보드 포커스와 스크린리더 이름을 확인한다.
- 이미지 크기, 레이아웃 이동, 모션 감소 설정을 확인한다.
- title, description, canonical, Open Graph, JSON-LD, sitemap, robots를 검증한다.

## 운영

- 배포·롤백 절차가 존재한다.
- 데이터 변경 전 백업 상태를 확인한다.
- 실패 시 기존 공개 사이트가 유지된다.
- 관찰 가능한 로그와 상태 확인 방법이 있다.

## 문서

- 관련 기준 문서와 ADR이 코드와 일치한다.
- PR에 검증 증거와 운영 영향을 기록한다.
- 남은 위험과 수행하지 않은 작업을 명시한다.
